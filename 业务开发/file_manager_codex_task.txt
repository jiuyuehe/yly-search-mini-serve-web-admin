# Codex Task: 文件管理页面 - 网格 / 列表双视图

你是一名前端工程师。请实现一个文件管理页面，支持“网格视图”和“列表视图”两种展示效果，并完善基础交互状态。页面应保持清晰、现代、易用，适合接入真实文件数据。

## 一、目标

实现一个 File Manager 页面，用户可以：
1. 在网格视图和列表视图之间切换。
2. 浏览文件与文件夹。
3. 搜索文件。
4. 按类型、名称、更新时间、大小进行排序或筛选。
5. 选择单个或多个文件。
6. 对文件执行基础操作：打开、重命名、下载、删除、更多操作。
7. 在空状态、加载状态、错误状态下有明确反馈。

## 二、页面结构

页面建议包含以下区域：

### 1. 顶部工具栏

包含：
- 页面标题：文件管理
- 搜索框
- 上传按钮
- 新建文件夹按钮
- 视图切换按钮：网格 / 列表
- 排序入口
- 筛选入口

交互要求：
- 搜索输入时实时过滤文件。
- 搜索为空时展示全部文件。
- 当前视图按钮应有明显选中态。
- 上传、新建文件夹可先实现 UI 和点击反馈，不需要真实后端。

### 2. 面包屑导航

示例：
全部文件 / 项目资料 / 设计稿

交互要求：
- 点击某一级面包屑可返回对应目录。
- 当前层级不可点击或弱化显示。
- 文件夹双击或点击进入后，面包屑应更新。

### 3. 文件展示区域

支持两种模式。

## 三、网格视图 Grid View

### 展示内容

每个文件或文件夹使用卡片展示，包含：
- 文件类型图标或缩略图
- 文件名
- 文件类型
- 更新时间
- 文件大小
- 更多操作按钮
- 选中复选框，默认隐藏，hover 或多选模式下显示

### 网格布局

要求：
- 响应式布局。
- 大屏每行 4-6 个。
- 中屏每行 3-4 个。
- 小屏每行 2 个。
- 卡片宽高统一，文件名超出时省略。

### 交互状态

每个卡片需要支持：
- hover：卡片浮起或背景变浅，显示快捷操作。
- selected：显示选中边框、背景色和复选框。
- focused：键盘聚焦时有明显 focus ring。
- loading：可用 skeleton 占位。
- disabled：操作不可用时降低透明度。

### 操作方式

- 单击卡片：选中文件，或打开详情面板。
- 双击文件夹：进入文件夹。
- 双击文件：打开预览。
- 点击更多按钮：打开下拉菜单。
- Cmd/Ctrl + 点击：多选。
- Shift + 点击：范围选择。
- Esc：取消选择。

## 四、列表视图 List View

### 展示内容

使用表格或行列表展示，每行包含：
- 复选框
- 文件图标
- 文件名
- 类型
- 更新时间
- 大小
- 所属者，可选
- 操作按钮

### 列表交互

要求：
- 表头支持点击排序。
- 当前排序字段显示升序 / 降序图标。
- 行 hover 时显示快捷操作。
- 多选后顶部出现批量操作栏。
- 长文件名省略，hover 可显示 tooltip。
- 点击行选中。
- 双击行打开文件或进入文件夹。

### 批量操作

当选中文件数量大于 0 时，显示批量操作栏：
- 已选择 N 项
- 下载
- 移动
- 删除
- 取消选择

## 五、通用状态

### 1. 空状态

无文件时显示：
- 插画或图标
- 文案：这里还没有文件
- 操作按钮：上传文件 / 新建文件夹

搜索无结果时显示：
- 文案：没有找到匹配的文件
- 操作按钮：清空搜索

### 2. 加载状态

页面初始加载时：
- 网格视图显示卡片 skeleton。
- 列表视图显示行 skeleton。

### 3. 错误状态

加载失败时显示：
- 错误提示
- 重试按钮

## 六、文件类型建议

请至少模拟以下类型：
- folder
- pdf
- doc
- xls
- ppt
- image
- video
- audio
- zip
- code
- unknown

不同类型使用不同图标或视觉标识。

## 七、数据结构

请使用 mock 数据，字段如下：

```ts
type FileItem = {
  id: string;
  name: string;
  type: "folder" | "pdf" | "doc" | "xls" | "ppt" | "image" | "video" | "audio" | "zip" | "code" | "unknown";
  size: number | null;
  updatedAt: string;
  owner?: string;
  path: string[];
  thumbnailUrl?: string;
};
```

## 八、状态管理

需要管理以下状态：
- viewMode: "grid" | "list"
- query: string
- currentPath: string[]
- selectedIds: string[]
- sortBy: "name" | "type" | "updatedAt" | "size"
- sortDirection: "asc" | "desc"
- isLoading: boolean
- error: string | null

## 九、组件建议

请尽量拆成以下组件：
- FileManagerPage
- FileToolbar
- Breadcrumbs
- ViewToggle
- SortDropdown
- FilterDropdown
- FileGrid
- FileCard
- FileList
- FileRow
- BulkActionBar
- EmptyState
- LoadingState
- ErrorState
- FileActionsMenu

## 十、视觉要求

- 整体风格简洁、现代、偏 SaaS 后台。
- 卡片圆角，轻阴影。
- hover、selected、active 状态清晰。
- 保证移动端可用。
- 保证基础无障碍：按钮有 aria-label，键盘 focus 可见。

## 十一、实现要求

请根据当前项目技术栈实现。如果项目是 React / Next.js：
- 使用 TypeScript。
- 使用函数组件。
- 使用 Tailwind CSS 或项目已有样式方案。
- 不需要真实后端，先用 mock 数据。
- 操作按钮可以先用 toast、console.log 或本地状态模拟。
- 代码需要可运行，不要只给伪代码。
- 保持组件清晰可维护。

## 十二、验收标准

完成后应满足：
1. 可以在网格和列表之间切换。
2. 搜索可以过滤文件名。
3. 排序可以改变展示顺序。
4. 文件和文件夹能被选中，多选状态正确。
5. 文件夹进入后面包屑变化。
6. 空状态、加载状态、错误状态组件存在。
7. 页面响应式表现正常。
8. 代码结构清晰，便于后续接真实 API。
